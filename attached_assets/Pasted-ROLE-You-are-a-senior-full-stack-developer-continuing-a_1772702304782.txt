[2] PUSH NOTIFICATION SYSTEM
Implement Web Push notifications using the browser Push API + Workbox.

SETUP:
  - Generate VAPID key pair (store private key as environment secret, public key in code)
  - Create endpoint in backend: POST /api/push/subscribe (saves subscription to DB)

TABLE: push_subscriptions
  id UUID PRIMARY KEY
  user_id UUID REFERENCES users(id)
  subscription JSONB (the full PushSubscription object)
  created_at TIMESTAMP DEFAULT now()

PERMISSION REQUEST TIMING (critical — wrong timing kills opt-in rates):
  - NEVER ask for notification permission on page load or signup
  - Ask ONLY after user completes their FIRST daily practice
  - Show a contextual prompt BEFORE the browser dialog:
    "Want a daily reminder to protect your streak? [Yes, remind me] [Not now]"
  - If they click "Yes", then trigger browser permission dialog
  - If browser grants permission, save subscription to push_subscriptions table

NOTIFICATION TRIGGERS (backend sends these):
  - Daily practice reminder: "🔥 Don't break your [X]-day streak. 15 minutes. That's all."
    Send at: user's preferred practice time (stored in profile from Phase 1)
    If no preferred time: send at 6 PM user local time
  - Streak at risk: "⚠️ Your [X]-day streak breaks in 2 hours. Quick practice now?"
    Send at: 10 PM local time if no practice logged that day
  - Badge earned: "[emoji] You just earned [Badge Name]! See your progress →"
    Send immediately when badge is awarded
  - New content unlocked: "🆕 [Content Name] just unlocked. You've earned it. →"
    Send when a level-gated feature becomes available

BUILD the push sending function as a Supabase Edge Function or backend route:
  POST /api/push/send
  Body: { userId, title, body, url }
  Looks up user's push_subscriptions, sends via web-push library
  Log all sends to a push_log table (user_id, notification_type, sent_at, success BOOLEAN)

  - Mark sent_at = now() after successful send

[3] BASIC COMMUNITY FORUM
Build a minimal but functional discussion forum. Keep it simple — no third-party forum
software. Build it in Supabase + React.

TABLE: forum_posts
  id UUID PRIMARY KEY
  user_id UUID REFERENCES users(id)
  module_context TEXT (e.g., 'week_2', 'general', 'neural_lab')
  title TEXT
  content TEXT
  created_at TIMESTAMP DEFAULT now()
  updated_at TIMESTAMP

TABLE: forum_replies
  id UUID PRIMARY KEY
  post_id UUID REFERENCES forum_posts(id)
  user_id UUID REFERENCES users(id)
  content TEXT
  created_at TIMESTAMP DEFAULT now()

TABLE: forum_reactions
  id UUID PRIMARY KEY
  post_id UUID (nullable) REFERENCES forum_posts(id)
  reply_id UUID (nullable) REFERENCES forum_replies(id)
  user_id UUID REFERENCES users(id)
  type TEXT ('fire', 'got_it', 'question')
  — NOTE: only one reaction per user per post/reply

FORUM UI:
  - Located at /community route
  - Tabs: [All Posts] [Week 1] [Week 2] [Week 3] [Week 4] [Week 5] [Week 6] [Neural Lab]
  - Each tab filters by module_context
  - Post list: shows title, author (display_name + level badge), reply count, time
  - Clicking a post opens full post + replies
  - "New Post" button (only visible to logged-in users)
  - Reaction buttons: 🔥 (fire) | ✅ (got it) | ❓ (question)
  - Each module's lesson page should have a link: "Discuss this in the community →"
    that pre-filters to that module's forum tab
